# v0.4.0 — Runtime wrappers and a harder audit

0.4.0 completes the loop from transcript audit to runtime enforcement, and hardens
the audit against the false positives found in real sessions and an external review.

## Runtime wrappers

- `LangGraphGuard` wraps `invoke` / `ainvoke`, records the graph state, and verifies
  it at the end of the run.
- `run_with_verification` and `run_with_verification_async` wrap OpenAI Agents SDK
  runs and return a verified result.
- `trace_from_langgraph_state`, `trace_from_run_result`, and
  `verify_langgraph_state` are available for custom runners.
- The wrappers are duck-typed; Assaystone does not import LangGraph or the OpenAI
  Agents SDK. See [docs/integrations.md](../integrations.md).

## Audit hardening

- Strict JSONL parsing reads records by newline, not `splitlines()`, so U+0085 and
  U+2028 inside a string cannot corrupt a transcript. Invalid lines are skipped with
  a warning.
- SARIF locations point at the artifact named in the finding, not the first artifact.
- `evidence.claims` infers test outcomes only from explicit runner commands
  (`pytest`, `npm test`, `go test`, and similar) and structured output. Ambiguous
  output leaves evidence unset instead of guessing.
- Workspace copies skip `.git`, `node_modules`, virtualenvs, caches, and build output,
  and refuse the home directory or filesystem root.
- Default forbidden paths are now CI workflows and actions, not all of `.github/`.
- Debug-print checks ignore CLI entry points, tests, examples, and scripts.
- Directory audits skip unreadable files with a warning; malformed trace objects are
  rejected before `Trace.from_dict`.
- The audit display uses a readable baseline label instead of a machine-specific
  absolute path.

## Field note

The 162-session Claude Code audit found test-directory activity, but no confirmed test
tampering in the five strongest candidates. The path-based rule reports activity, not
intent. That is why the Stop hook defaults to `warn`, and why an intent-aware
`tests.weakened` check is on the roadmap. Read the full note:
[docs/case-study-2026-11.md](../case-study-2026-11.md).

## Install

```bash
pip install --upgrade assaystone==0.4.0
assaystone demo audit
```

No runtime dependencies. Python 3.10+.

## Known limitations

- `tests.integrity` is path-based; it cannot tell a legitimate test refactor from a
  deleted assertion. Use the hook in `warn` mode until you tune the contract.
- Bash file writes are visible to the hook through git working-tree changes; a plain
  transcript audit without `--git-repo` may miss them.
- LangSmith, Langfuse, and OpenTelemetry importers are heuristic.
- `--run-tests` executes the project's test command in a temporary copy. It is not a
  sandbox; only audit repositories you trust.
