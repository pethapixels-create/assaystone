# v0.5.0 — One-command audits and Codex support

Assaystone 0.5.0 makes the first useful run much shorter and extends the audit to
Codex CLI sessions.

## Highlights

- **Audit the latest session without finding a path**

  ```bash
  pip install assaystone
  assaystone audit --latest claude-code
  assaystone audit --latest codex
  ```

  `--latest` finds the newest transcript whose recorded working directory contains
  the current directory. Transcripts stay local.

- **Codex CLI transcripts**

  Assaystone now reads Codex session JSONL, reconstructs `apply_patch` changes, and
  recognizes `exec_command` test runs when inferring test evidence.

- **Action outputs**

  The composite GitHub Action now exposes `verdict`, `findings`, and `traces` for
  downstream jobs.

- **A cleaner release and contributor path**

  Root-level `pytest` now collects only the project tests. The wheel and sdist exclude
  `__pycache__` and `.pyc` files. CI covers Python 3.10 through 3.13, lint, coverage,
  package installation, and all three demos. The Makefile selects an available Python
  3.10+ interpreter and adds `make pytest`, `make lint`, and `make package`.

- **Claude Code plugin**

  Add the repository as a marketplace and install the plugin:

  ```text
  /plugin marketplace add yellowsand1/assaystone
  /plugin install assaystone@assaystone
  ```

  The plugin adds `/assaystone:audit`, `/assaystone:setup`, and a fail-open Stop hook.
  `claude plugin validate --strict` passes locally and in CI.

- **Project site**

  The landing page lives at <https://yellowsand1.github.io/assaystone/>.

## Upgrade

```bash
pip install --upgrade assaystone==0.5.0
assaystone --version
```

For the GitHub Action, pin `yellowsand1/assaystone@v0.5.0`.

## Known limits

- `--latest` depends on the local Claude Code or Codex session directory layout. Use
  `ASSAYSTONE_CLAUDE_ROOT` or `ASSAYSTONE_CODEX_ROOT` when those tools store sessions
  elsewhere.
- Codex `apply_patch` is replayed. Arbitrary shell writes still need `--git-repo`.
- The default test-integrity rule is path-based and reports test-directory changes;
  it does not infer intent.
